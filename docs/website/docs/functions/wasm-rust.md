# WebAssembly functions in Rust

The Rust guest SDK is `raisin-sdk` (`sdks/rust/raisin-sdk` in the repository).
It gives you typed wrappers for the whole `raisin.*` surface, a handler macro,
and a mock host so `cargo test` runs your handlers natively — no wasm, no
server.

```bash
raisindb create function greet --lang rust
```

## A function

```rust
use raisin_sdk::prelude::*;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)] struct Input { name: String }
#[derive(Serialize)]   struct Output { greeting: String, people: usize }

#[raisin_sdk::handler]                   // registered as "default"
fn greet(input: Input) -> Result<Output> {
    raisin_sdk::log::info(format!("greeting {}", input.name));
    let people = raisin_sdk::nodes::get_children("content", "/people", None)?;
    Ok(Output { greeting: format!("Hello, {}!", input.name), people: people.len() })
}

#[raisin_sdk::handler(name = "shout")]   // registered as "shout"
fn shout(input: Input) -> Result<Output> {
    Ok(Output { greeting: format!("HELLO, {}!", input.name.to_uppercase()), people: 0 })
}

raisin_sdk::export!(greet, shout);
```

A handler is `fn(I) -> raisin_sdk::Result<O>` with `I: Deserialize` and
`O: Serialize`; the error type only needs `Display`, so `anyhow` and `thiserror`
work. Empty input arrives as JSON `null`.

## Two macros, and why

`#[handler]` names a handler and wraps it in its JSON envelope. `export!` lists
the handlers, builds the dispatch table and emits the component's single WIT
export.

The list is explicit on purpose. `inventory`/`linkme`-style registration
collects through constructors or linker sections; on `wasm32-wasip2` an empty
slice would be indistinguishable from a component that registered nothing, and
the failure would surface only at run time on a server. A handler missing from
`export!` is a compile error instead — and `export!` is the one place
`raisindb function doctor` reads to check an `entry_file` handler name.

## Cargo

```toml
[lib]
crate-type = ["cdylib", "rlib"]   # "rlib" too, so tests/ can link the crate

[profile.release]
opt-level = "s"
lto = true
panic = "abort"
strip = true
codegen-units = 1
```

```bash
rustup target add wasm32-wasip2
cargo build --release --target wasm32-wasip2
# target/wasm32-wasip2/release/<crate_name>.wasm  ~200-400 KB
```

`wasm32-wasip2` emits a component directly (rustc ≥ 1.82) — no
`cargo-component` step, though `cargo component build` also works.
`raisindb function build` runs the command and copies the output to the Function
node's `main.wasm`; it scrubs `CARGO_TARGET_DIR`, `RUSTFLAGS`,
`CARGO_ENCODED_RUSTFLAGS` and `CARGO_BUILD_RUSTFLAGS`, because this repository's
`.cargo/config.toml` sets `split-debuginfo`, which does not exist on wasm32.

## Testing, natively

On a non-wasm target the SDK's host routes to a scripted mock instead of the WIT
imports, so handlers, the generated wrappers and `Transaction` all run their
real code:

```rust
use raisin_sdk::testing::{with_mock, MockHost};

let mock = MockHost::new().expect("nodes_get", r#"["content","/x"]"#, Ok("null".into()));
let (result, mock) = with_mock(mock, || raisin_sdk::nodes::get("content", "/x"));
assert!(mock.unmet().is_empty());
```

An unscripted call is an `Err`, never a default answer. `raisin_dispatch(name,
input)` — generated by `export!` — invokes a named handler directly, exactly as
the host would.

## Conventions

- **Every host error is an `Err`**, including an `Ok` body carrying
  `{"error": true, "message": …}` — a few host methods answer that way, and
  treating it as data would carry a failure forward as success.
- `raisin_sdk::Transaction` rolls back on drop unless committed.
- `Context::get()` reads the dedicated `context` WIT import, not the gateway, so
  it costs no round trip.
- `println!` / `eprintln!` reach the logs but carry no level — prefer
  `raisin_sdk::log::*`.
- Egress is `raisin_sdk::http::*` only; the host links neither `wasi:sockets`
  nor `wasi:http`. See [Limits and sandbox](./wasm-limits.md).

`src/generated.rs` and `wit/raisin-function.wit` are machine-owned
(`make gen-bindings`). Do not run `cargo fmt` inside the SDK: rustfmt follows
`mod generated;` and makes the freshness test permanently red.
